# AutoApp

대중교통 경로 검색과 실시간 도착정보를 제공하는 로컬 웹앱입니다. Windows와 Node.js 24에서 실행하며 추가 패키지 설치가 필요하지 않습니다.

## 실행

1. 저장소를 내려받고 프로젝트 폴더에서 터미널을 엽니다.
2. `.env.example`을 `.env`로 복사해 본인의 API 인증키를 입력합니다.
3. `npm start`를 실행합니다. PowerShell 실행 정책 오류가 있으면 `npm.cmd start`를 사용합니다.
4. 브라우저에서 `http://127.0.0.1:4317`로 접속합니다. 종료는 터미널에서 `Ctrl+C`입니다.

키 없이도 화면을 열 수 있지만 실제 검색에는 인증키와 서비스 승인이 필요합니다. 키 변경 후 서버를 재시작합니다. `.env`와 개인 설정은 Git에 포함하지 않습니다.

| 환경변수 | 용도 |
| --- | --- |
| KAKAO_REST_API_KEY | 주소·장소 검색 |
| ODSAY_API_KEY | 대중교통 경로 검색 |
| SEOUL_SUBWAY_API_KEY | 지하철 실시간 도착정보 |
| SEOUL_BUS_API_KEY | 서울 버스 정류소정보조회 |
| GYEONGGI_BUS_API_KEY | 경기도 버스도착정보 조회 v2 |

버스는 각각의 서비스 활용 승인이 필요합니다. ODsay 서버 IP 제한을 사용하는 경우 실행 환경의 외부 공인 IP를 등록해야 합니다.

선택 사항: `local-settings.example.json`을 `local-settings.json`으로 복사하고 이동 이름, 출발지 주소, 도착지 장소명을 지정하면 초기 입력값으로 사용합니다. 이 파일도 Git에서 제외됩니다.

## 구현 기능

- 주소·장소 검색, 출발지·도착지 맞바꾸기
- 브라우저 저장, 불러오기, 수정, 복사 저장, 삭제
- 예상 소요시간 → 환승 횟수 → 도보시간 순으로 정렬하고 첫 경로에 ‘최적’ 표시
- 버스·지하철 탑승 횟수, 도보 구간 합산 시간, 예상 요금 표시
- 경로 상세 및 서울·경기 버스와 지원 지하철 실시간 도착정보
- 수동 새로고침과 화면을 보는 동안 30초 자동 갱신

## 범위와 제한

저장은 브라우저 localStorage를 사용합니다. 로그인·DB·기기 간 동기화·위치 추적·하차 알림·설치형 iOS 앱은 아직 구현하지 않았습니다. 지하철은 수도권 1~9호선 범위에서 역명과 다음 역 방향을 매칭하며, 종착역·급행 정차 여부는 별도 확인이 필요합니다. ‘최적’ 정렬은 실시간 대기시간을 반영하지 않습니다.

실시간 결과는 조회 시점에 따라 달라집니다. 경로 조회 토큰은 서명된 교통 구간 정보를 담으며 30분간 유효합니다. 서로 다른 서버 인스턴스에서도 사용할 수 있고, 만료되면 다시 검색합니다. 로컬 실행은 해당 컴퓨터에서만 접속하도록 설정돼 있으며 Vercel 배포도 지원합니다.

앱 화면에는 출처·제공기관 생성 시각·내부 캐시 정책을 표시하지 않는 원칙을 유지합니다.

## 검증

```sh
npm test
npm run check
```

실서비스 검증 도구 `verify-live.mjs`, `inspect-transit.mjs`, `diagnose-arrivals.mjs`는 실제 키와 인터넷 연결이 필요합니다. 앞의 두 도구는 `local-settings.json`의 출발지 주소와 한국금융연수원 시험 경로를 사용하며 `--reverse`로 반대 방향을 확인할 수 있습니다.

## Vercel 배포

2026-11-03: `Invalid export found in module server.mjs` 오류를 해결하기 위해 기본 요청 처리 함수를 내보내고, `api/` 아래에 Vercel 함수 진입점을 추가했습니다. `vercel.json`은 화면을 `public/`에서 정적 제공하고 API만 함수로 실행하도록 지정합니다.

1. GitHub `main`의 최신 커밋으로 배포합니다. Root Directory는 저장소 최상위(기본값)입니다.
2. Framework Preset은 **Other**, Output Directory는 **public**, Build Command는 **npm run check**, Node.js는 **24.x**입니다. 저장소의 설정 파일과 package.json에 지정돼 있습니다. Build Command에 `npm start`를 지정하지 않습니다.
3. Vercel 프로젝트의 Settings → Environment Variables에 위 표의 다섯 API 키를 등록합니다. 운영 배포는 Production에 적용합니다. Preview에서도 시험하려면 해당 환경에도 등록합니다. GitHub에 `.env`를 올리지 않습니다.
4. 환경변수를 변경했다면 새 배포를 실행합니다. 기존 오류 배포의 고정 URL 대신 새 배포의 Visit 또는 프로젝트 운영 도메인으로 접속합니다.
5. `/api/status`에서 JSON이 반환되는지 확인하고 주소 검색 → 양방향 경로 검색 → 상세 도착정보를 확인합니다. `true`는 키가 설정됐다는 의미이며 유효성은 실제 조회로 확인해야 합니다.

별도 DB 없이 동작하도록 경로 토큰은 ODsay 키를 이용해 용도가 구분된 HMAC으로 서명합니다. 선택적으로 `ROUTE_TOKEN_SECRET`을 별도 비밀 환경변수로 지정할 수 있습니다. 서명 키를 바꾸면 기존 토큰은 무효가 되므로 경로를 다시 검색합니다. 토큰에는 교통 역·정류장 정보만 담고 API 키나 검색한 상세주소는 담지 않습니다.

Vercel에는 노트북의 `.env`, 개인 설정 또는 브라우저 저장 목록이 자동 전달되지 않습니다. 배포 주소의 저장 목록도 로컬 주소와 별개입니다. ODsay에 IP 제한이 있으면 Vercel에서 사용하는 외부 호출 IP의 허용 조건을 별도로 확인해야 합니다. 화면 정상 접속과 외부 교통 API 승인·연결은 별도 검증 항목입니다.
