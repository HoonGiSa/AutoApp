대중교통 경로·실시간 도착정보 앱
중간 결과물 실행 안내서
제출본 기준일: 2026-10-07

1. 제출물 개요
Windows 노트북에서 실행하는 웹앱의 소스 코드입니다. 시연은 개발자의 노트북에서 진행합니다. 온라인 배포본이나 설치형 iOS 앱이 아닙니다.
ZIP을 해제하면 commute-pilot 폴더에 프로그램, 설정 예시, 테스트, 본 안내서가 있습니다. HTML 화면 파일만 직접 열면 API 기능이 작동하지 않습니다. 아래 절차로 서버를 실행해야 합니다.

2. 구현된 기능
• 주소 또는 장소 검색 및 출발지·도착지 선택
• 출발지와 도착지 맞바꾸기
• 이동 정보 저장·불러오기·수정·다른 이름으로 저장·삭제
• 대중교통 경로 검색 및 구간별 상세 보기
• 소요시간 → 환승 횟수 → 도보시간 순으로 경로 정렬, 첫 경로에 ‘최적’ 표시
• 버스·지하철 탑승 횟수, 전체 도보시간, 예상 요금 표시
• 선택 경로의 서울·경기 버스와 지원 지하철 도착정보 조회
• 수동 새로고침 및 화면을 보는 동안 30초 자동 갱신

3. 실행 환경
검증 환경: Windows, Node.js 24, 인터넷 연결, 웹브라우저.
Node.js 공식 설치 페이지: https://nodejs.org/
별도 npm 패키지를 사용하지 않으므로 npm install은 필요하지 않습니다.
실제 주소·경로·도착정보를 조회하려면 API 인증키와 해당 서비스 이용 승인이 필요합니다.
인증키가 없어도 서버와 화면은 열리지만 실제 조회는 할 수 없습니다. 키 없는 모의 시연 데이터는 포함하지 않았습니다.

4. 최초 설정
① ZIP을 완전히 압축 해제합니다.
② package.json과 server.mjs가 있는 commute-pilot 폴더를 엽니다.
③ .env.example 파일을 같은 폴더에 복사하고 복사본 이름을 .env로 바꿉니다.
   Windows 탐색기에서 파일 확장명을 표시하고 .env.txt가 되지 않도록 확인합니다.
④ .env의 등호 오른쪽에 본인의 인증키를 입력하고 저장합니다.

KAKAO_REST_API_KEY: 주소·장소 검색용 REST API 키
ODSAY_API_KEY: 대중교통 경로 검색용 키
SEOUL_SUBWAY_API_KEY: 서울시 지하철 실시간 도착정보 인증키
SEOUL_BUS_API_KEY: 서울 버스 정류소정보조회 서비스 인증키
GYEONGGI_BUS_API_KEY: 경기도 버스도착정보 조회 서비스 v2 인증키

버스 서비스는 공공데이터포털에서 각각 활용 신청해야 합니다. 버스 키는 디코딩 키 사용을 권장합니다. ODsay에 서버 IP 제한을 설정했다면 실행하는 네트워크의 외부 공인 IP를 허용해야 합니다. 키 변경 후에는 서버를 재시작합니다.
실제 인증키와 개발자의 개인 설정 파일은 제출본에서 제외했습니다. 이메일로 API 키를 함께 전달하지 않습니다.

5. 실행과 종료
commute-pilot 폴더에서 PowerShell 또는 명령 프롬프트를 열고 실행합니다.

  node --version
  npm start

정상 실행 시 다음 주소가 표시됩니다.
  http://127.0.0.1:4317

브라우저 주소창에 이 주소를 입력합니다. 서버가 실행된 터미널은 열어 둡니다.
종료하려면 터미널에서 Ctrl+C를 누릅니다.
PowerShell에서 npm.ps1 실행 정책 오류가 발생하면 다음 명령을 사용합니다.
  npm.cmd start
또는 다음 명령으로 직접 실행합니다.
  node --env-file-if-exists=.env server.mjs

6. 시연 순서
① 이동 이름에 ‘시험 경로’를 입력합니다.
② 출발지 검색 유형을 장소 검색으로 선택하고 ‘철산역’을 검색해 광명 소재 결과를 선택합니다.
③ 도착지에서 ‘한국금융연수원’을 검색해 ‘서울 종로구 삼청로 118’인 결과를 선택합니다.
④ ‘새 이동 저장’을 누르고 저장한 이동 목록에서 ‘불러오기’를 확인합니다.
⑤ ‘경로 찾기’를 누릅니다. 첫 경로의 ‘최적’, 탑승 횟수, 도보시간, 예상 요금을 확인합니다.
⑥ ‘이 경로 자세히 보기’를 눌러 구간별 정보와 실시간 도착정보를 확인합니다.
⑦ 출발지·도착지 맞바꾸기 버튼을 누르고 경로를 다시 조회해 반대 방향을 확인합니다.
⑧ 이동 이름 또는 장소를 수정해 저장하고, ‘다른 이름으로 추가 저장’과 삭제를 확인합니다.

개발자 노트북 시연에서는 기존 설정의 자택 ↔ 한국금융연수원 시험 경로를 사용할 수 있습니다. 제출본에는 자택 주소나 기존 브라우저 저장 목록을 포함하지 않았습니다.
실시간 응답은 조회 시각과 운행 상황에 따라 달라지므로 특정 경로 수·소요시간·열차 수가 고정되지 않습니다.

7. 현재 제한 사항
• 저장 정보는 해당 브라우저의 localStorage에 보관됩니다. 다른 컴퓨터·브라우저·접속 주소에 자동 공유되지 않습니다.
• 최적 경로는 조회된 예상 소요시간 등을 기준으로 정렬합니다. 현재 열차·버스의 대기시간까지 반영한 최적화는 아닙니다.
• 도보시간은 출발·환승·도착 도보 구간을 합산합니다. 원본 시간이 누락되면 정보 없음으로 표시될 수 있습니다.
• 지하철은 수도권 1~9호선 범위에서 역명·호선·다음 역 방면을 맞춥니다. 종착역과 급행 정차 여부는 탑승 전에 확인해야 합니다.
• 실시간 도착정보는 지금 승차 지점에 오는 차량 정보이며, 미래 환승 시점의 예측이 아닙니다.
• 위치 추적, 하차 알림, 로그인·권한, DB 저장, 가전 제어, 가계부, 투자 기능, iOS 앱은 아직 구현하지 않았습니다.
• 이 서버는 해당 컴퓨터 내부에서만 접속할 수 있습니다. 외부 공개용 보안·배포 설정은 포함하지 않았습니다.

8. 문제 해결
연결할 수 없음: 서버 터미널이 실행 중인지 확인하고 http://127.0.0.1:4317로 접속합니다.
EADDRINUSE: 같은 포트의 기존 개발 서버가 실행 중인지 확인합니다. 기존 터미널에서 종료하거나 기존 서버 화면을 사용합니다.
node 명령을 찾을 수 없음: Node.js 설치 후 터미널을 새로 엽니다.
키 필요·조회 실패: .env 파일명, 서비스 승인 상태, 키 종류, IP 허용 설정, 호출 한도 및 인터넷 연결을 확인합니다.
도착정보 없음: 현재 해당 노선·방향의 응답이 없는 상태일 수 있습니다. 자동으로 운행 종료를 뜻하지 않습니다.
경로 조회 만료: 경로 토큰은 30분간 유효합니다. 서버를 재시작했거나 만료되었다면 ‘경로 찾기’를 다시 누릅니다.
저장한 이동이 보이지 않음: 기존과 같은 브라우저·프로필·접속 주소인지 확인합니다. 브라우저 데이터 삭제 시 저장 목록도 삭제됩니다.

9. 검증 방법
API 키 없이 다음 명령으로 자동 테스트를 실행할 수 있습니다.
  node --test routes.test.mjs arrivals.test.mjs arrival-display.test.mjs storage.test.mjs
구문 검사는 다음 명령으로 실행합니다.
  npm run check
테스트는 저장 처리, 경로 정렬·합산, 방향 매칭, 도착정보 표시 등을 검증합니다. 외부 API의 실시간 정확도나 모든 지역의 운행을 보장하는 검사는 아닙니다.

10. 주요 파일
server.mjs: 로컬 서버, 주소·경로 API 및 실시간 조회 연결
routes.mjs: 경로 요약, 정렬, 탑승 횟수와 도보시간 계산
arrivals.mjs: 실시간 도착정보 조회 및 노선·방향 매칭
public/: 화면, 스타일, 브라우저 저장 처리
*.test.mjs: 자동 테스트
.env.example: 빈 인증키 설정 예시
package.json: 실행 및 구문 검사 명령

실제 .env, 개인 설정, 브라우저 저장 데이터, Git 기록은 제출본에 포함하지 않습니다.
